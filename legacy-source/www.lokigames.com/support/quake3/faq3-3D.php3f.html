3D/Graphics Quake III only runs in Mesa software mode -- only one frame every few seconds.
3dfx users must have /dev/3dfx installed or run as root, or Mesa may revert to software mode.

Another possibility is that the game is trying to use an r_mode that is not supported by your XF86Config. For example, 532x384 is supported by 3dfx cards, but if you don't have this mode defined in your XF86Config file, then the VideoModeExtension required for fullscreen mode will fail.

To exit software Mesa quickly, press UPARROW once in the main menu (will bring you down to "Exit"), RETURN, LEFTARROW (to switch to "Yes"), RETURN, RETURN. This will take only a few frames/seconds.

To install /dev/3dfx, please visit www.3dfxgamers.org and obtain Device3Dfx-2.3-1.src.rpm. Follow the instructions there to compile and install the kernel module. You might also want to add a line like alias char-major-107 3dfx to /etc/conf.modules to make sure the module is loaded automatically.

To enable 532x384 or other non-standard resolutions, you will have to add a Modeline "532x384" line to your /usr/X11R6/lib/X11/XF86Config or /etc/X11/XF86Config file.

Finally, Q3A might be using a software-only or outdated Mesa DLL in your system. Please use ldconfig -v | grep GL to check for another libGL.so or libMesaVoodooGL.so in your system. Q3A does search the linker paths for other GLs. If you are running with root privileges, it will ignore the GL in the local directory. On vid_restart (resolution change and other display configuration), it might also find a different GL even if you started it with the right one (using +set r_glDriver). Another application may be blocking /dev/dsp. Quake III initializes Glide before initializing sound, and will fail prior to rendering the first video frame if it is unable to access to the sound device. If this happens, you can exit cleanly by typing "~" to get into the console, then typing "quit" followed by RETURN (all blindly).
